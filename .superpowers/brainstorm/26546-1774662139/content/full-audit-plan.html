Nonco Stables — Design Audit Completo

Análise page-by-page com olhar de designer e dev senior. Cada issue tem severidade, diagnóstico e fix proposto.

Critical — quebra a experiência
High — impacta usabilidade
Medium — polish visual
Low — detalhe fino

🏗 Global — Sistema de Design

HIGHInconsistência de espaçamento entre páginas
Algumas páginas usam space-y-8, outras space-y-6. Card padding varia entre px-5 py-3 e px-6 py-4. Não há ritmo visual consistente.
Padronizar: todas as páginas usam space-y-6 entre seções. Card headers sempre px-6 py-3. Card body sempre p-6. Form spacing space-y-4.
HIGHFont size drift em labels
Section labels alternam entre text-[10px] e text-[11px]. Tracking varia entre 0.08em, 0.1em, e 0.15em.
Criar 3 tiers fixos: micro-label = text-[9px] tracking-[0.12em], label = text-[11px] tracking-[0.1em], body = text-sm.
MEDIUMTicker global vs contextual
O ticker foi adicionado ao layout global mas agora está no main de todas as páginas com px-6 md:px-8 mb-6. Em páginas como API Keys e Third Party, rates FX são irrelevantes.
Mover ticker para DENTRO das páginas que precisam: Dashboard, FX Board, e Wallet. Remover do layout global. Ou: deixar global mas com design mais sutil — altura 28px, sem border, opacidade 60%, integrado ao header.
MEDIUMAusência de page titles/headers claros
O PageHeader mostra "Nonco / Page Title" como breadcrumb mas algumas páginas ainda usam SectionLabel como pseudo-título. Não há hierarquia clara de "onde estou".
Cada página deve ter um header consistente: título grande (h1, text-xl font-bold) + subtítulo descritivo. O breadcrumb do header já existe — as pages não precisam de SectionLabel como primeiro elemento.

📊 Dashboard

7.5/10
HIGHCompetição visual entre BalanceHero e QuickActions
O hero chart (lado esquerdo) e quick actions (lado direito) competem por atenção em grid 1:1. O chart é denso e detalhado, mas os quick actions são simétricos e ocupam o mesmo espaço visual. Resultado: nenhum dos dois se destaca.
Fazer o hero chart full-width (100%), mover quick actions para uma row horizontal abaixo do hero (flex row com 4-5 pills inline, similiar ao wallet hero). Isso dá ao chart o protagonismo que merece e os quick actions ficam como nav secundária.
MEDIUMCurrencyBreakdown com DonutChart duplica informação
O donut chart + legend + table mostram os mesmos 5 currencies 3 vezes. A informação não progride — é redundante.
Simplificar: donut com legend inline no header da table (uma única row), sem duplicar a lista. Ou: remover donut do breakdown e manter só na wallet page (onde faz mais sentido como portfolio view).
MEDIUMMarket Watch grid e Activity competem na mesma row
Market Watch (2x3 grid) e Activity (lista de transações) lado a lado em grid 1:1. Em telas < 1024px empilham mal. A Activity fica comprimida.
Market Watch full-width (1 row de 6 cards em grid-cols-3 md:grid-cols-6). Activity abaixo, full-width, com max 4-5 items e "View all" link.
LOWDeskOfferBanner animação banner-shimmer pode ser distrativa
A animação de 4s infinite no gradiente de fundo pode cansar em uso prolongado.
Reduzir a 1 iteração ou manter mas com animation-fill-mode: forwards após 2 ciclos.

💰 Wallet

8/10
MEDIUMHero donut + balance poderia ter mais impacto
O donut está a 140px e o balance em text-5xl. Em telas grandes, a área tem muito espaço vazio entre os dois. A composição não é equilibrada.
Aumentar donut para 160-180px em desktop. Ou: inverter layout — balance gigante em cima, donut menor abaixo com legend horizontal. O número é o protagonista, não o chart.
MEDIUMAction pills poderiam ser mais distintas
5 action pills com ícones muito similares (todos círculos cyan com arrows). Difícil distinguir rapidamente Send de Receive de Deposit.
Usar cores diferentes por ação: Receive=green, Send=red/amber, Convert=cyan, Earn=purple, Deposit=white. Ou: usar ícones mais distintos (não apenas arrows).
LOWHoldings table sparklines são muito sutis
Sparklines a 48x24px com cor do currency são quase invisíveis no fundo escuro. Não agregam informação útil no tamanho atual.
Aumentar para 64x28px e adicionar area fill (não só stroke). Ou: remover sparklines da table e deixar o donut como única viz nesta page.

📈 FX Board

8.5/10
MEDIUMBoard muito largo para telas médias
8 colunas com larguras fixas (w-8, w-20, w-28, etc.) totalizam ~700px mínimo. Em telas 1024-1200px com sidebar, o conteúdo fica apertado ou overflow.
Esconder colunas Sell qty e Prev close em hidden xl:flex. Manter: Status, Pair, Sell price, Buy price, Buy qty, 24h change. Desktop full mostra tudo.
LOWSection separators são muito discretos
As section dividers (LATAM, BRL, EUR, GBP) são quase invisíveis: dot 2px + text 10px em bg opacity 0.02. Perdem-se no contexto das rows.
Aumentar presença: dot para 6px, left-border de 3px na cor da seção, ou background gradient sutil da cor da seção (opacity 0.04).

🏦 Yield Vaults

8/10
HIGH4 vault cards em 1 row é apertado
Em xl:grid-cols-4 os cards ficam estreitos (~220px cada). O APY grande (28px) + chart + stats + button criam scroll interno. Em MD ficam 2 colunas que é melhor.
Mudar para grid-cols-1 md:grid-cols-2 lg:grid-cols-3 max. O 4º vault (coming-soon) pode ficar como um card menor ou um "banner" de "GBP vault coming soon" ao invés de um card completo.
MEDIUMMetrics strip sem hierarquia
4 métricas lado a lado com tamanhos iguais. "Total Deployed" ($1.84M) é a métrica principal mas tem o mesmo peso visual que "Blended APY".
Fazer "Total Deployed" span 2 cols ou ter font-size maior (text-3xl). As outras 3 ficam menores. Hierarquia: 1 metric hero + 3 secondary.

💸 Payments

7/10
HIGHForm muito longo sem agrupamento visual
O form de pagamento tem 7 campos + flow diagram + quote summary + button empilhados. Parece uma parede de inputs. Não há agrupamento visual.
Dividir em 3 grupos visuais com dividers ou cards internos: (1) "From" — send from + amount, (2) "To" — recipient + CLABE + currency, (3) "Summary" — flow diagram + quote + button. Cada grupo com um mini-header de seção.
MEDIUMFlowDiagram hardcoded, não reage ao form
O FlowDiagram mostra "USDT $240,000 → MXN 4,181,798" hardcoded. Deveria reagir ao amount e currency selecionados no form.
Conectar FlowDiagram ao form state. Calcular dynamically: from.value = formatted amount, to.value = amount × rate, rate = rate do par selecionado.

🌐 Bridge & Onchain

6.5/10
HIGHPáginas parecem landing pages, não app pages
Bridge e Onchain usam layout centered com heading grande + subtítulo + form card. Parecem páginas de marketing, não seções de um app. A data-grid-bg ajuda mas não resolve.
Repensar como app pages: remover headings gigantes, usar o card diretamente com o form como elemento principal. Adicionar sidebar info ou stats cards que deem contexto (ex: Bridge — "6 chains supported, avg time 45s, $2.4M bridged this month").
MEDIUMFeature pills no bottom são genéricos
Os pills "Fast", "Secure", "6 chains", "Low fees" parecem copy de landing page. Não agregam valor funcional dentro do app.
Substituir por dados reais em cards: "Avg settlement: 45s", "Chains: ETH, Base, SOL...", "Fee: ~$0.80". Informação > marketing.

📋 Trades

8/10
MEDIUMVolume by Pair chart é muito comprimido
As bars de volume por pair ficam em 2.5px de height (h-2.5) e são difíceis de ler. O gradient de cyan é quase imperceptível.
Aumentar bars para h-4 ou h-5. Usar cor sólida com opacity tiers ao invés de gradient fino. Ou substituir por mini bar-chart vertical (como o BarChart component).

⏱ Settlements

7.5/10
MEDIUMProgress rings adicionados mas sem contexto claro
Os ProgressRing (T+1 58%, T+2 18%) foram inseridos mas o "58%" não é auto-explicativo. 58% do quê?
Adicionar tooltip ou sublabel: "58% complete" → "58% — $108K of $186K settled". O ring precisa contar uma história, não só mostrar um número.

📊 Reports

7.5/10
HIGHPeriod selector não muda dados
Os pills MTD/30d/QTD/YTD são clicáveis mas todos mostram os mesmos dados hardcoded. Dá sensação de bug.
Adicionar pelo menos 2-3 datasets diferentes (MTD vs 30d vs QTD) com variações nos números. Ou: manter MTD como único e remover os outros pills até ter dados reais.
MEDIUMBarChart muito pequeno relativo à table
O BarChart com height=80 acima de uma table detalhada parece um afterthought. É a viz principal da página mas não tem presença.
Aumentar BarChart para height=120-140. Ou: fazer o chart full-width acima da two-column layout, como hero da página.

🔑 API Keys & Third Party

7/10
MEDIUMPages muito simples — parecem "admin panels"
API Keys e Third Party são basicamente uma table com filtros. Não têm nenhum grafismo ou viz que dê personalidade. Parecem um CRUD admin genérico.
API Keys: adicionar usage stats (requests/day mini chart, last 7 days). Third Party: adicionar payment volume by payee mini viz. Nem toda page precisa de um hero chart, mas algum elemento visual que não seja "só texto + table".

🧩 Layout Global

CRITICALTicker no layout global polui páginas não-trading
O ticker está em (app)/layout.tsx como <div className="px-6 md:px-8 mb-6"><TickerBar /></div>. Aparece em TODAS as páginas, incluindo API Keys, Reports, Settings. Rates FX são irrelevantes nessas páginas e adicionam ruído visual.
Opção A: Mover ticker para dentro de Dashboard, FX Board e Wallet apenas (3 páginas onde rates importam). Opção B: Integrar ao sidebar (bottom section) como lista vertical compacta — sempre visível mas sem ocupar espaço do conteúdo. Opção C: Manter global mas como um "collapse" no page-header: ícone de "rates" que expande/colapsa a faixa.
HIGHPageHeader breadcrumb não aproveita o espaço
O header mostra "Nonco / Dashboard" em texto pequeno. O resto do header é espaço vazio (notification bell + avatar à direita). 64px de height para tão pouca informação é desperdício.
Integrar o ticker ao header: "Nonco / Dashboard" à esquerda, ticker scrolling ao centro, notification + avatar à direita. Usa o espaço que já existe sem adicionar uma nova barra.
